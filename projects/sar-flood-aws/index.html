Summary

The flood model from the segmentation pipeline, deployed as a live serverless inference API. You POST a Sentinel-1 scene and get back a flood mask and a GeoJSON of flood polygons. The inference can outrun API Gateway's 29 second limit, so the API is asynchronous: submit a job, poll for status, download the result from a presigned URL.

SageMaker Serverless Inference runs the model and scales to zero, so idle cost is zero. Everything is infrastructure as code: the whole stack comes up from a clean account with one cdk deploy and goes back to zero with cdk destroy.

1 What it does

Research shows you can build the model. This shows you can ship it.

The caller uploads a Sentinel-1 scene to S3 through a presigned URL, then submits a job to a REST API protected by an API key and a per-day usage plan. A Lambda kicker writes job state to DynamoDB, reads the scene, invokes the SageMaker endpoint, writes the mask and GeoJSON back to S3, and returns presigned download URLs. The client polls until the job is done. The API reproduces the local inference mask bit for bit.

Scaling to zero is the point: with nothing to serve, the stack costs nothing, and a cold start pays a one-time penalty to wake the endpoint. AWS Budgets alarms and an S3 seven-day lifecycle keep the running cost bounded and self-cleaning.

4 Infrastructure as code and CI/CD

Everything is AWS CDK in Python. One command brings the stack up from a clean account, another takes it back to zero. GitHub Actions builds the container, pushes it to ECR, and redeploys on every push to main, authenticating to AWS with OIDC so there are no long-lived AWS keys in the repository.

deployAWS CDK (Python)
cdk deploy      # bring the whole stack up from a clean account
cdk destroy     # take it back to zero
